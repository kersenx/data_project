
> **一句话总结**：指标体系的本质，是围绕业务目标，将目标拆解为一套口径统一、层级清晰、可度量、可追踪、可归因的指标结构。

> 个人理解： 指标体系就是针对业务目标（北极星指标）进行体系化的， 可度量的拆解；
> 通过拆解让业务目标从“模糊愿望”变成“可度量、可监控、可分析、可优化”的指标结构
## 一、什么是指标体系

指标体系**围绕业务目标**，把业务过程拆解成**可度量、可追踪、可归因**的一套指标结构。

对数据研发来说，它的价值有四点：

1. **统一口径**：避免“销售额”“活跃用户”“转化率”每个部门算法不同。
2. **量化和拆解目标**： 把业务目标变成可度量的数字
3. **支撑归因分析/问题定位**：让业务问题可以被拆解、定位、归因。
4. **指导数据建设**：决定数仓分层、主题域、宽表、看板和数据服务如何设计。


## 二、指标的分类与分层

> 指标既可以按**计算方式**分类，也可以按**业务作用**分类，还可以按**体系层级**分层。

| 类型       | 定义                  | 例子              |
| -------- | ------------------- | --------------- |
| **原子指标** | 不可再拆的基础度量           | 订单数、支付金额        |
| **派生指标** | 原子指标 + 时间 + 维度 + 修饰 | 近7日支付金额、新客支付GMV |
| **复合指标** | 由多个指标计算得到           | 转化率、客单价、退款率     |

### 1. 按计算方式分类

#### 1.1 原子指标

原子指标是**不可再拆**的基础度量，通常由一个业务动作或事实表字段聚合而来：

```text
支付金额   = sum(订单实付金额)
订单数     = count(distinct 订单ID)
支付用户数 = count(distinct 用户ID)
```

#### 1.2 派生指标

派生指标是在原子指标基础上，加上**时间周期、业务限定、统计维度**形成的指标。

```text
近7日支付金额
昨日新用户支付金额
本月华东地区成交订单数
APP端新客支付转化率
```

**派生指标 = 原子指标 + 时间周期 + 修饰词 + 统计维度 + 业务口径**。

#### 1.3 复合指标

复合指标由多个指标计算得来，常见于**比率、均值、效率**类指标。

```text
客单价 = 支付金额   / 支付订单数
转化率 = 支付用户数 / 访问用户数
退款率 = 退款订单数 / 支付订单数
ROI    = 收益       / 成本
```

> ⚠️ 复合指标很常问，因为它最容易暴露候选人是否真正理解**分子、分母、统计口径和异常处理**（比如分母为 0、分子分母时间窗不一致）。

### 2. 按业务作用分类：过程指标与结果指标

除了按计算方式分为原子、派生、复合指标，也可以按**业务作用**分为过程指标和结果指标。

| 类型 | 回答的问题 | 例子 | 作用 |
| --- | --- | --- | --- |
| **结果指标** | 最终结果好不好？ | GMV、支付金额、订单数、推广流水、利润 | 判断业务目标是否达成 |
| **过程指标** | 结果是怎么形成的？ | 曝光量、点击率、加购率、下单率、支付转化率 | 解释结果变化、定位问题、指导优化 |

以电商为例：

```text
曝光 -> 点击 -> 浏览 -> 加购 -> 下单 -> 支付
```

对应关系可以理解为：

```text
过程指标：曝光量、点击率、浏览量、加购率、下单率、支付转化率
结果指标：支付订单数、支付金额、GMV
```

> 注意：过程 / 结果是按“业务作用”分类，原子 / 派生 / 复合是按“计算方式”分类，两者不是同一个维度。比如“支付转化率”按计算方式是复合指标，按业务作用通常是过程指标。

### 3. 按体系层级分层

> 一个清晰的指标体系通常是**金字塔结构**：北极星指标在顶，逐层向下拆解到可执行的诊断指标。

```text
北极星指标（1个）
   └─ 一级指标（业务目标）
        └─ 二级指标（解释一级）
             └─ 诊断指标（定位问题）
```

#### 3.1 北极星指标

**北极星指标（One Metric That Matters）**是最能代表业务长期增长的核心指标。

| 业务 | 北极星指标 |
| --- | --- |
| 电商 | GMV、支付用户数、复购用户数 |
| 内容平台 | 有效观看时长、日活用户数 |
| SaaS | 付费客户数、续费收入 |
| 出行平台 | 完成订单数 |

> ⚠️ 北极星指标**不能只看规模，要结合质量**。例如电商只看 GMV，会忽略退款率、补贴成本和真实利润。

北极星指标原则上在一个业务阶段内应该只有一个，用来统一业务增长方向。但不同业务线、不同产品阶段可以有各自的北极星指标。北极星下面可以拆多个一级指标和诊断指标，用来解释和驱动它。

#### 3.2 一级指标

**一级指标是对北极星指标的第一层拆解**，对应驱动最终目标的关键业务**方向**。
根据北极星指标拆解业务过程/方向；
一级指标是对北极星指标的拆解，表示要从哪些业务目标或关键环节去驱动它。
北极星指标回答“最终追什么”；一级指标回答“靠哪些方面把它做上去。
以电商为例：流量规模、用户转化、商品供给、交易结果、履约体验、售后质量。

#### 3.3 二级指标

> **二级指标是对一级指标的继续拆解，用来解释某个关键业务方向为什么变好或变差。**

```text
访问用户数 -> 加购用户数 -> 下单用户数 -> 支付用户数
访问→加购转化率 / 加购→下单转化率 / 下单→支付转化率
```

#### 3.4 诊断指标

诊断指标可以理解为对核心指标、一级指标或二级指标的进一步下钻。它在形式上是继续拆解，在作用上是为了定位问题原因。
例如 GMV 下降时：

```text
GMV = 流量 × 转化率 × 客单价
```

继续拆：

```text
流量   = 曝光人数 × 点击率
转化率 = 支付用户数 / 访问用户数
客单价 = 支付金额 / 支付订单数
```

这样就能判断 GMV 下滑到底是**流量问题、转化问题，还是客单价问题**。

## 三、主流方法论（加分项）

> 面试中能说出方法论名字，比只会罗列指标更显体系感。

| 方法论       | 适用场景      | 核心思想                                               |
| --------- | --------- | -------------------------------------------------- |
| **OSM**   | 通用指标拆解    | Objective（目标）→ Strategy（策略）→ Measure（度量），从业务目标反推指标 |
| **UJM**   | 用户旅程分析    | User Journey Map，沿用户路径设计过程指标                       |
| **AARRR** | 增长 / 用户运营 | 获取→激活→留存→变现→传播（海盗模型）                               |
| **指标分级**  | 指标管理      | 北极星 → 一级 → 二级 → 诊断，自上而下                            |


**OSM + UJM 组合**是设计指标体系最常用的搭配：OSM 定“看什么目标”，UJM 把目标落到“用户每一步”。

### 实战案例：用方法论拆解华为应用市场（AG）

> 以华为应用市场（AppGallery，简称 AG）为例，演示 OSM + UJM + AARRR + 指标分级 如何组合落地。

**业务背景**：AG 的核心商业化是**应用推广**——开发者（广告主 / CP）付费购买曝光和下载位，平台按下载 / 时段 / 点击计费。
因此 AG 的**北极星指标是「推广流水」**（广告消耗 = Σ 计费事件 × 单价）。

#### 1. OSM：从目标反推策略与度量

| O 目标   | S 策略           | M 度量               |
| ------ | -------------- | ------------------ |
| 推广流水增长 | 扩大流量盘子         | AG 活跃用户数、曝光量       |
|        | 提升转化效率         | 点击率、下载转化率、激活率      |
|        | 提升广告主续投意愿（ROI） | 激活率、留存率、卸载率 ↓      |
|        | 提升变现效率         | eCPM、CPD 单价、计费下载占比 |

> 广告主真正买的不是“下载”，而是“留下来的有效用户”。**留存差 → 广告主 ROI 差 → 不续投 → 流水掉**，所以留存 / 卸载也属于商业化指标，而不只是产品指标。

#### 2. UJM：沿用户旅程设计过程指标

```text
打开 AG     →  推广位曝光   →  点击   →  下载    →  安装/激活   →  使用      →  留存
(活跃/DAU)     (曝光 PV/UV)    (点击)    (下载量)    (激活量)       (时长/频次)   (次留/7留)
                                                       ↘ 卸载（负向流失）
```

| 环节      | 过程指标              | 转化率           |
| ------- | ----------------- | ------------- |
| 活跃 → 曝光 | 推广请求量、曝光 PV/UV、人均曝光 | **推广填充率** |
| 曝光 → 点击 | 点击 PV/UV          | **点击率 CTR**   |
| 点击 → 下载 | 下载量               | **下载转化率 CVR** |
| 下载 → 激活 | 激活量               | **激活率**       |
| 激活 → 留存 | 次日 / 7 日 / 30 日留存 | **留存率**       |
| 反向      | 卸载量               | **卸载率**       |

#### 3. AARRR：映射到商业化漏斗

| 阶段                 | AG 对应指标                      |
| ------------------ | ---------------------------- |
| **Acquisition 获取** | AG 活跃用户、曝光量                  |
| **Activation 激活**  | 点击、下载、应用激活                   |
| **Retention 留存**   | 使用时长 / 频次、次日 / 7 日留存、卸载率（反向） |
| **Revenue 变现**     | 推广流水、eCPM、ARPU、CPD 单价        |
| **Referral 传播**    | 评分、好评率、分享 / 推荐               |

#### 4. 指标分级：搭成金字塔

```text
北极星：推广流水
  └─ 一级：流量规模 / 转化效率 / 变现效率 / 用户质量
       └─ 二级：曝光量、点击率、下载转化率、激活率、eCPM、留存率
            └─ 诊断：分渠道 / 分广告位 / 分应用类目 / 分新老用户 下钻
```

#### 5. 流水公式拆解（诊断核心）⭐

```text
推广流水 = 曝光量 × 点击率 × 下载转化率 × 计费下载占比 × CPD 单价
```

换用户视角再拆一版：

```text
推广流水 = AG活跃用户 × 人均曝光 × 点击率 × 下载率 × 计费占比 × 单价
```

流水下降时，逐个因子排查：

| 下降因子      | 排查方向                  |
| --------- | --------------------- |
| 活跃 / 曝光 ↓ | 大盘 DAU、广告位数量、推荐策略     |
| 点击率 ↓     | 素材质量、排序算法、广告位位置       |
| 下载转化率 ↓   | 详情页、网络 / 包体大小、应用本身吸引力 |
| 计费下载占比 ↓  | 刷量过滤、无效下载、广告主预算耗尽     |
| CPD 单价 ↓  | 竞价激烈度、广告主结构、行业淡旺季     |

#### 6. AG 特有的口径坑 ⚠️

| 指标   | 口径要点                            |
| ---- | ------------------------------- |
| 曝光   | 区分 PV / UV；同一广告位多次刷新是否去重        |
| 下载   | “发起下载” ≠ “下载完成” ≠ “安装完成” ≠ “激活” |
| 激活   | 通常定义为 App **首次成功打开**            |
| 留存   | 激活后第 N 日是否再次打开（按设备还是账号去重）       |
| 计费下载 | 只有**有效 / 新增**下载才计费，需过滤刷量、重复设备   |

## 四、指标体系建设方法

> 第三节的方法论是“工具箱”，第四节讲实际落地流程：先明确目标，再拆指标、定维度、定口径，最后落到模型、字典和质量监控。

### 1. 明确业务目标

先问业务到底想解决什么：**增长、留存、转化、收入、成本、风险、效率**。

> 没有业务目标的指标体系，很容易沦为**指标堆砌**。

可以用 **OSM** 来辅助拆解：

```text
Objective：业务目标是什么？
Strategy：通过哪些策略达成？
Measure：用哪些指标衡量策略是否有效？
```

### 2. 梳理业务过程

用 **UJM / AARRR** 梳理用户或业务链路，明确每个环节发生了什么。

以电商为例，典型链路：

```text
曝光 -> 点击 -> 浏览 -> 加购 -> 下单 -> 支付 -> 发货 -> 签收 -> 复购
```

每个环节都可以设计**过程指标**和**结果指标**。

### 3. 进行指标分层拆解

围绕业务目标，先确定北极星指标，再向下拆成一级指标、二级指标和诊断指标。

```text
北极星指标：最终追什么
一级指标：靠哪些关键方向驱动
二级指标：每个方向具体看哪些指标
诊断指标：异常时继续下钻定位原因
```

例如电商 GMV：

```text
北极星：GMV
  └─ 一级：流量规模 / 转化效率 / 客单价 / 复购
       └─ 二级：访问用户数、支付转化率、人均订单数、客单价
            └─ 诊断：分渠道、分商品类目、分新老用户、分地区下钻
```

### 4. 设计分析维度

指标必须配合维度使用，才能支持对比、下钻和归因。

常见维度包括：

| 维度  | 示例                       |
| --- | ------------------------ |
| 时间  | 日 / 周 / 月 / 小时 / 活动期     |
| 用户  | 新老客 / 会员等级 / 城市 / 设备     |
| 渠道  | APP / 小程序 / H5 / 搜索 / 推荐 |
| 商品  | 类目 / 品牌 / SPU / SKU      |
| 活动  | 大促 / 优惠券 / 满减 / 直播间      |
| 场景  | 页面 / 入口 / 广告位 / 版本       |

> 没有维度的指标只能“看结果”，不能解释结果为什么变化。

### 5. 确定业务口径 

> **口径是指标体系的灵魂**，面试和实战中 80% 的指标争议都来自口径不清。

口径必须明确五件事：

| 要素   | 要回答                 |
| ---- | ------------------- |
| 统计对象 | 用户、订单、商品、商家？        |
| 统计周期 | 日、周、月、近7日？          |
| 过滤条件 | 是否剔除测试 / 取消 / 退款订单？ |
| 时间字段 | 创建时间、支付时间、完成时间？     |
| 去重逻辑 | 按用户ID、设备ID，还是账号ID？  |

**反例 vs 正例**——“昨日订单金额”必须写清楚：

```text
按支付时间统计，统计昨日 00:00:00 至 23:59:59 已支付订单的实付金额，剔除测试订单和风控订单。
```

### 6. 确定技术口径： 明确数据来源和模型落地

数据研发不能只停留在业务定义，还要确认指标能不能稳定生产。

需要明确：

```text
指标来自哪张事实表？
依赖哪些维表？
在 DWD / DWS / ADS 哪一层沉淀？
是离线 T+1，还是实时 / 准实时？
是否需要沉淀为公共指标，供多个看板复用？
```

常见落地方式：

```text
DWD 明细事实表 -> DWS 主题汇总表 -> ADS 应用看板表 / 指标平台
```

> 指标通常优先依赖 DWS 层，因为 DWS 是面向主题的公共汇总层，粒度适中、复用性强、查询效率更高。DWD 提供明细事实来源，适合追溯口径和重新加工，但直接算指标可能粒度过细、成本较高；ADS 面向具体应用或看板，复用性较弱。实际建设中没有绝对限制，具体依赖哪一层要看指标粒度、复用范围和性能要求。

形成指标， 以前很多指标要数据研发手写 SQL；有指标平台后，标准指标可以基于 DWS / 指标层，通过配置指标定义、维度、过滤条件和计算规则来生成查询或服务。就像现在的指标中心；

### 7. 建立指标字典
建好了指标就需要写个说明书给大家用， 这就是指标字典； 
指标字典是用来统一管理指标定义、口径、计算逻辑、维度、数据来源和负责人的文档或系统，核心作用是保证大家对同一个指标理解一致、计算一致、使用一致。
通常包含：

```text
指标名称 / 指标编码 / 指标类型 / 业务定义 / 计算公式
统计周期 / 统计维度 / 数据来源 / 负责人 / 更新时间 / 使用场景
```

> 💡 指标字典相当于指标体系的说明书，主要用于**统一口径和指标资产管理**。它不是直接展示业务结果的报表，而是让不同角色在使用指标时有统一的定义、计算逻辑和数据来源，避免同名不同义、重复开发和口径不一致。

### 8. 指标验收和质量监控

核心指标上线前要做口径评审和数据验收，上线后要持续监控质量。

常见检查项：‘一拳击准稳’

| 检查项 | 说明               |
| --- | ---------------- |
| 准确性 | 与业务系统、财务口径或旧报表对账 |
| 完整性 | 是否漏数据、漏分区、漏渠道    |
| 及时性 | 是否按 SLA 产出       |
| 稳定性 | 同比、环比是否出现异常波动    |
| 一致性 | 同一指标在不同看板是否口径一致  |

> 指标体系不是“定义完就结束”，还要能长期稳定、可信、可复用。

## 五、案例：华为应用市场推广流水指标体系

假设要为华为应用市场（AppGallery，简称 AG）的**应用推广商业化**建设指标体系。

### 1. 明确业务目标

AG 的推广商业化，本质是开发者 / 广告主付费购买应用曝光、点击、下载或推广资源位。

业务目标可以概括为：

```text
提升应用推广商业化收入，同时保证用户体验和广告主投放效果。
```

因此，北极星指标可以设为：

```text
推广流水 = 广告主在应用推广上的实际消耗金额
```

> 注意：推广流水不能只看收入规模，还要结合用户质量、广告主 ROI、留存和卸载率，否则可能短期收入提升，但长期广告主不续投。

### 2. 梳理业务过程

从用户旅程看，AG 推广业务链路可以拆成：

```text
打开 AG -> 推广位曝光 -> 点击 -> 下载 -> 安装 -> 激活 -> 使用 -> 留存 / 卸载
```

从商业化计费看，可以拆成：

```text
流量曝光 -> 用户行为转化 -> 有效计费事件 -> 广告主消耗 -> 推广流水
```

也就是说，这里有两条漏斗：

```text
用户行为转化漏斗：曝光 -> 点击 -> 下载 -> 安装 -> 激活 -> 留存
收入转化漏斗：曝光 / 点击 / 下载 -> 有效计费事件 -> 广告消耗 / 推广流水
```

### 3. 进行指标分层拆解

```text
北极星：推广流水
  └─ 一级：流量规模 / 用户转化效率 / 商业变现效率 / 用户质量 / 广告主健康度
       └─ 二级：曝光量、CTR、下载转化率、激活率、eCPM、CPD单价、留存率、续投率
            └─ 诊断：分渠道、分广告位、分应用类目、分素材、分新老用户、分广告主下钻
```

| 层级    | 指标     | 说明                       |
| ----- | ------ | ------------------------ |
| 北极星指标 | 推广流水   | 衡量 AG 推广商业化最终收入结果        |
| 一级指标  | 流量规模   | 有没有足够用户和推广曝光机会           |
| 一级指标  | 用户转化效率 | 用户从曝光到点击、下载、安装、激活的行为漏斗效率 |
| 一级指标  | 商业变现效率 | 用户行为转化为计费事件和收入的效率        |
| 一级指标  | 用户质量   | 下载用户是否真实、有留存、低卸载         |
| 一级指标  | 广告主健康度 | 广告主是否愿意持续投放和提高预算         |

### 4. 设计二级指标

| 一级指标   | 二级指标                               | 含义              |
| ------ | ---------------------------------- | --------------- |
| 流量规模   | AG 活跃用户数、推广请求量、推广填充率、曝光 PV/UV、人均曝光 | 衡量流量盘子和推广资源填充情况 |
| 用户转化效率 | CTR、下载转化率、安装完成率、激活率                | 衡量用户行为是否逐步转化    |
| 商业变现效率 | eCPM、CPC、CPD 单价、计费下载占比、预算消耗率       | 衡量流量和转化能否变成收入   |
| 用户质量   | 次留、7留、30留、使用时长、卸载率                 | 衡量推广带来的用户是否有效   |
| 广告主健康度 | 广告主数量、投放应用数、续投率、ROI、预算消耗率          | 衡量广告主供给和续投意愿    |

### 5. 设计分析维度

| 维度 | 示例 |
| --- | --- |
| 时间 | 日 / 周 / 月 / 小时 / 活动期 |
| 渠道 | 推荐页、搜索页、榜单页、详情页、活动页 |
| 广告位 | 首页推荐位、搜索广告位、详情页推荐位 |
| 应用 | 应用 ID、应用类目、应用大小、付费 / 免费 |
| 广告主 | 广告主类型、行业、投放预算、投放目标 |
| 用户 | 新老用户、设备类型、地区、系统版本 |
| 素材 | 标题、图标、文案、落地页版本 |

### 6. 设计核心指标口径

| 指标 | 口径要点 |
| --- | --- |
| 曝光 | 区分 PV / UV；同一广告位多次刷新是否重复计数 |
| 推广填充率 | 实际返回推广内容的请求量 / 可展示推广的请求量，用来衡量推广资源是否填满流量坑位 |
| 点击 | 是否去重；是否过滤误触、异常点击 |
| 下载 | 区分发起下载、下载完成、安装完成、首次打开 |
| 激活 | 通常定义为 App 首次成功打开 |
| 计费下载 | 只有有效 / 新增下载才计费，需要过滤刷量、重复设备、无效下载 |
| 推广流水 | 统计周期内广告主因有效计费事件产生的实际消耗金额 |
| 留存 | 激活后第 N 日是否再次打开，需明确按设备还是账号去重 |
| 卸载率 | 统计周期内卸载用户数 / 激活用户数，需明确观察窗口 |

### 7. 核心公式拆解

从商业化链路看：

```text
推广流水 = 曝光量 × 点击率 × 下载转化率 × 计费下载占比 × CPD 单价
```

如果从推广请求开始拆，可以把曝光量再拆一层：

```text
曝光量 = 推广请求量 × 推广填充率
推广流水 = 推广请求量 × 推广填充率 × CTR × 下载转化率 × 计费下载占比 × CPD单价
```

从用户规模看：

```text
推广流水 = AG活跃用户数 × 人均曝光 × CTR × 下载转化率 × 计费下载占比 × CPD单价
```

如果推广流水下降，可以按因子定位：

| 下降因子 | 排查方向 |
| --- | --- |
| AG 活跃用户数 ↓ | 大盘用户活跃、版本变化、渠道流量变化 |
| 人均曝光 ↓ | 广告位数量、推荐策略、流量分发策略 |
| CTR ↓ | 素材质量、广告位位置、推荐相关性、应用吸引力 |
| 下载转化率 ↓ | 详情页、网络环境、包体大小、用户意愿 |
| 计费下载占比 ↓ | 无效下载、刷量过滤、重复设备、预算耗尽 |
| CPD 单价 ↓ | 竞价激烈度、广告主结构、行业淡旺季 |

### 8. 明确数据来源和模型落地

| 数据层 | 可能沉淀内容 |
| --- | --- |
| ODS | 曝光日志、点击日志、下载日志、安装 / 激活日志、计费流水原始表 |
| DWD | 曝光明细、点击明细、下载明细、激活明细、计费明细、广告主投放明细 |
| DWS | 广告位粒度汇总、应用粒度汇总、广告主粒度汇总、用户转化漏斗汇总 |
| ADS | 推广经营看板、广告主效果报表、渠道分析报表、应用推广复盘报表 |

> 实际上 ODS / DWD / DWS / ADS 都可能被用来算指标，但核心公共指标通常优先沉淀在 DWS 或指标层，保证复用性、性能和口径统一。

### 9. 建立指标字典和质量监控

指标字典需要记录：

```text
指标名称 / 指标编码 / 业务定义 / 计算公式 / 统计周期
统计维度 / 数据来源 / 负责人 / 更新时间 / 使用场景
```

质量监控重点包括：

```text
曝光、点击、下载、激活、计费流水是否延迟；
推广流水是否和财务 / 计费系统对账一致；
CTR、下载转化率、eCPM 是否出现异常波动；
同一指标在经营看板、广告主报表、复盘报表中口径是否一致。
```

面试总结可以这样说：

> 以华为应用市场推广商业化为例，我会先明确北极星指标为推广流水，再按流量规模、用户转化效率、商业变现效率、用户质量和广告主健康度拆一级指标；二级指标包括曝光量、CTR、下载转化率、激活率、eCPM、CPD 单价、留存率、续投率等；然后按渠道、广告位、应用类目、广告主、用户类型等维度下钻，最后明确每个指标的口径、数据来源、模型落地和质量监控。

## 六、数据研发在指标体系中的职责

数据研发不只是“实现指标 SQL”，还要：

1. 理解业务过程，**协助定义指标口径**。
2. 建设数据模型，**保障指标可复用**。
3. 建设**统一指标层**，减少重复开发。
4. 保障指标质量（准确性、稳定性、时效性）。
5. 推动指标**文档化、资产化、服务化**。

常见落地链路：

```text
ODS -> DWD -> DWS -> ADS -> BI / API / 指标平台
```

| 层 | 职责 |
| --- | --- |
| **DWD** | 沉淀明细事实 |
| **DWS** | 沉淀主题汇总（指标复用的关键层） |
| **ADS** | 面向具体应用 |
| **指标平台** | 统一管理指标定义和计算逻辑 |

> 🔧 **趋势**：很多公司已从“手写指标 SQL”转向**指标平台 / 指标中台**（如阿里 OneData、各类一站式指标平台），通过配置化方式统一口径、自动生成查询，避免“同名不同义”。

## 七、全文总结

指标体系的核心不是罗列一堆指标，而是围绕业务目标，把业务过程拆成**可度量、可追踪、可归因、可复用**的一套结构。

可以用一条主线记住全文：

```text
业务目标 -> 指标分类与分层 -> 方法论拆解 -> 口径和维度设计 -> 数仓模型落地 -> 指标字典和质量监控
```

### 1. 指标体系看三件事

| 问题  | 含义                     |
| --- | ---------------------- |
| 看什么 | 有哪些核心指标、过程指标、结果指标、诊断指标 |
| 怎么算 | 指标口径、公式、时间周期、过滤条件、去重逻辑 |
| 怎么用 | 支撑监控、分析、归因、经营决策和数据服务   |

### 2. 指标分类要分清维度

| 分类角度  | 类型                 | 重点            |
| ----- | ------------------ | ------------- |
| 按计算方式 | 原子 / 派生 / 复合       | 指标是怎么计算出来的    |
| 按业务作用 | 过程 / 结果            | 指标在业务链路里起什么作用 |
| 按体系层级 | 北极星 / 一级 / 二级 / 诊断 | 指标之间怎么拆解和下钻   |

面试中要注意：这些不是互斥分类。同一个指标可能既是复合指标，也是过程指标；也可能既是北极星指标，也是结果指标。

### 3. 建设指标体系的标准流程

```text
明确业务目标
 -> 梳理业务过程
 -> 进行指标分层拆解
 -> 设计分析维度
 -> 设计指标口径
 -> 明确数据来源和模型落地
 -> 建立指标字典
 -> 做指标验收和质量监控
```

其中最关键的是：

- **目标清楚**：知道业务到底要增长、转化、留存、收入还是降本；
- **拆解清楚**：能从北极星指标拆到一级、二级和诊断指标；
- **口径清楚**：统计对象、周期、过滤条件、时间字段、去重逻辑要明确；
- **落地清楚**：指标来自哪层数据模型，沉淀在哪一层，谁负责维护；
- **质量清楚**：指标要能对账、准时产出、口径一致、趋势合理。

### 4. 数据研发要体现的能力

数据研发在指标体系里不只是写 SQL，而是要能把业务口径落到稳定的数据模型和指标服务中：

```text
懂业务 -> 定口径 -> 建模型 -> 沉淀公共指标 -> 保证质量 -> 服务报表 / API / 指标平台
```

面试时可以强调：

> 核心公共指标通常优先沉淀在 DWS / 指标层，但实际没有绝对限制，ODS、DWD、DWS、ADS 都可能被用于指标计算，关键看指标粒度、复用范围、性能要求和治理要求。

### 5. 一句话面试总结

> 指标体系是围绕业务目标，对业务过程和结果进行系统化度量的一套方法。设计时要先明确目标，再用 OSM、UJM、AARRR 等方法梳理业务链路，确定北极星指标并逐层拆解为一级、二级和诊断指标；同时要设计清楚指标口径、分析维度、数据来源、模型落地、指标字典和质量监控，最终让指标能被统一理解、统一计算、稳定复用。

## 八、面试常问问题

### 1. 什么是指标体系？

指标体系是**围绕业务目标，对业务过程和结果进行系统化度量**的一套指标集合，包括核心指标、过程指标、诊断指标和派生指标，并要求**统一口径、统一计算、统一管理**。

### 2. 原子指标、派生指标、复合指标有什么区别？

- **原子指标**：基础度量，如订单数、支付金额。
- **派生指标**：原子指标 + 时间 + 维度 + 修饰，如近7日支付金额。
- **复合指标**：多个指标计算得到，如转化率、客单价、退款率。

### 3. 如何设计一个电商指标体系？

先**明确业务目标**，再用 UJM **梳理用户链路**（曝光→点击→浏览→加购→下单→支付→履约→售后），然后围绕流量、转化、交易、商品、用户、履约、售后设计指标，并明确每个指标的**口径、维度和数据来源**。

### 4. GMV 下降你会怎么分析？

按公式拆解定位：

```text
GMV = 流量 × 转化率 × 客单价
GMV = 支付用户数 × 人均订单数 × 客单价
```

再分别看流量来源、转化漏斗、商品结构、活动策略、价格带、优惠力度、新老客结构。**先用公式定位到哪个因子，再下钻找原因**。

### 5. 如何保证指标口径一致？

通过**指标字典、指标平台、统一数据模型、公共汇总层、代码评审、口径评审、数据质量监控**来保障。关键原则：**核心指标不能由各业务方各自写 SQL，必须沉淀到统一指标层**。

### 6. 如果两个部门对同一个指标口径有争议怎么办？

**先看使用场景**：
- 场景不同 → 保留多个指标，但**命名必须清晰**（如“下单 GMV”和“支付 GMV”）。
- 场景相同 → 由**业务负责人 + 数据负责人共同确认唯一口径**，并写入指标字典。
